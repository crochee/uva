三个宿主等价：能力矩阵 原型 · 一次性

用一张表表达"终端 TUI / 浏览器 Web / 桌面 Desktop 各自能做什么"，并用五条规则守住它。

这份 demo 要回答的问题："三个宿主等价"这套定义与门禁规则，站得住吗？

表有 11 个核心能力域（会话、对话、Agent、技能、工具、任务、计划、评测、模型、搜索、UI 扩展）， 每行三列（三个宿主）。每格是四种状态之一：完整（能力齐、呈现等价）、 适配（能力齐、但按介质换了呈现，比如终端里的表格）、待做（能力还不齐）、 不适用（这个介质压根用不上，必须写明理由）。

五条规则：① 每行三列都要有值；② 待做格必须带锚点（说清打算什么时候做），不适用格必须带理由； ③ 完整 / 适配格必须指向磁盘上真实存在的证据文件；④ 缺口数（待做 + 不适用）只能下降，不能回升； ⑤ 格子里引用的服务器方法名必须真的存在。

波次推进时，缺口怎么降、非法格会不会被拦住——点按钮自己推。
