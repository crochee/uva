# Composition primitives

The round-by-round inventory of the composition primitives Uva added, kept out of the README so the front door stays a front door. Each row is a capability, not a release note — the authoritative API surface is each crate's rustdoc and `README.md`; the authoritative *history* is [`CHANGELOG.md`](../CHANGELOG.md).

The round labels (R9, R10–R13, …) refer to the internal development rounds recorded in `CHANGELOG.md`'s historical round log.

## Composition primitives added in R9

The workspace also ships four small lego primitives
that turn the assembly above into a typed configuration, layered
skill registry, and runtime-neutral spawn surface:

| # | Primitive | Crate | What it gives you |
|---|---|---|---|
| 1 | `ProviderProfile` + `ProviderRegistry` | `uva-provider` | Typed `enum` for OpenAI / Anthropic / Stub profiles; `ProviderRegistry::build(name)` returns `Box<dyn ModelProvider>` |
| 2 | `SkillProvider` + `SkillRegistry` | `uva-skill` | Plug any source of skills (filesystem, in-memory, remote) into one deduplicated registry |
| 3 | `SkillApplication` / `SkillApplicationContext` | `uva-skill` | Opt-in structured I/O for procedural skills: `SkillRequest → SkillResponse` closure |
| 4 | `HookMap::on_with_state` / `dispatch_with_state` | `uva-steering` | Hook handlers that read `&AgentState` (pi `harness/hooks.ts` parity) |
| 5 | `OperationSnapshot` / `OperationState` | `uva-session` | Read-only status record (running / completing / failed / cancelled + iteration + usage + last error / compaction) |
