# 一轮子会话归一个模块

「一轮子会话是什么、怎么开始、怎么结束、报告什么」这句话，在 `uva-tool-task` 里被写了
两遍，而且两遍已经不一致（下表是**改之前**的样子）：

| 事 | 委派路径（`task` 工具） | 唤醒路径（`agents_message`） |
|---|---|---|
| 结果里的子会话句柄 | 带 `[subagent session: <id>]` | **不带** |
| 深度规则 | 上限判定 + 记账 | **没有**（唤醒路径不问上限） |
| 结局的词 | 名册 `finished` / `cancelled` / `failed` | 退出脚手 `completed` / `cancelled` / `error` |
| 轮次流程 | 自己搭：抽干同伴 → 挂尾巴 → 映射结束原因 → 落尾巴 | 自己搭了第二遍同样的骨架 |

这不是 cosmetic。**同一个子会话，从两条路醒来，模型拿到的东西不一样**；「子会话能套
几层」有两套答案（其中一套根本没有）；「一轮结束了」有三处各写一份词表。

本 ADR 裁定：一轮子会话归一个模块（`round`），两条调用方只装配输入、拿结果值；深度
规则归同一个模块的子模块（`round::depth`）；一轮的**结局**只有一套词。

## 决定

### 1. 结局词归一：一套词，三处写

名册的活动行、L1 进度行的收尾摘要、子会话的 `subagent_exit` 脚手，写的是同一件事：
这一轮结束了。所以它们说同一个词，词表由 `RoundOutcome::as_str()` **一处**给出：

| 结局 | 词 | 名册活动行 | L1 进度行 | 退出脚手 |
|---|---|---|---|---|
| 跑完 | `completed` | `completed` | `completed` | `completed` |
| 被停 | `cancelled` | `cancelled` | `cancelled` | `cancelled` |
| 出错 | `error` | `error` | `error` | `error` |

名册原先写 `finished` / `failed`，现在写 `completed` / `error`。

### 2. 为什么是这三个词

因为这三个词**已经在用**：退出脚手写的就是它们，运行时自己的结束原因
`SessionEndReason::as_str()` 的前三个也是它们（`completed` / `cancelled` / `error`）。
归一是把名册与脚手**对齐到既有词汇**，不是新造一套词——新造词只会再多一种说法。

### 3. 原因轴与结局轴是两轴

结局说「这一轮结束了没有」，原因说「为什么结束的」。模型可见的失败文案说的是**原
因**（`max_iterations` / `suspended` / `config_drift` / `error` …），**不换成结局词**：
换成 `error` 会把「跑完了但没说话」和「跑崩了」说成同一件事。结局词只出现在写结局的
三处（名册、进度行、脚手）。

失败文案另外带上结束原因自带的**详情**（`SessionEndReason::Error(msg)` 的 `msg`）：
模型只知道「失败」不知道「为什么」是没有用的，`the peer gave up` 与「服务商拒了
key」不该读成同一句。

### 4. 深度规则的主体是**发起轮次的那一方**

上限判定的**主体**是发起轮次的那一方——`task` 的调用方、`agents_message` 的调用
方——**不是孩子**。理由：两条路的「发起轮次」动作都发生在调用方身上（`task` 调用
起孩子的第一轮，`agents_message` 调用起孩子的下一轮），孩子的深度是**记账**，不是判
定。

由此有三条推论：

- **唤醒路径问调用方**，不是问孩子。一个已经在上限层的**子会话**被唤醒时**不被拒**：
  树没有变深，被唤醒的轮次跑在孩子自己的深度上。
- **调用方在上限层时被拒**，即使它要唤醒的孩子也在上限层：主体是调用方，调用方坐
  上限就是被拒。
- 这条拒绝在**进程内**其实不可达：一个坐在上限层的会话持有不了孩子（它在上限层就
  不能再派发），所以它没有可唤醒的对象。规则仍然写在模块里，因为「唤醒路径也要有
  同一个上限」是这条纪律本身，不是当前可达性的证明。

### 5. 唤醒路径的新拒绝（模型可见的新行为）

`agents_message` 在调用方坐上限时拒绝，文案逐字是：

```text
cannot start another round: maximum sub-agent depth (3) reached; the `agents_message` tool is disabled at this nesting level
```

这是**新行为**：唤醒路径原先根本不问上限。被拒的轮次不跑，同伴一次都不被叫醒。

拒绝只覆盖**要起轮次**的分支（追问、冷唤醒）。**steer 不起轮次**，所以 steer 不会
被这条规则拒——拒绝文案说的是「cannot start another round」，拿它去拒一条不起轮次
的消息是文不对题。判定用的分支在动手改行**之前**读出来，于是被拒的行原样留在原地
（`idle` 还是 `idle`）。

### 6. 结果形状归一：两条路同形

- 两条路的结果都带 `[subagent session: <id>]` 句柄行；
- 失败文案**逐字相同**（同一个模块的同一个函数产出）；
- 委派路径的失败文案里，句柄行前**由单换行变双换行**：委派路径原先自己拼那句（一个
  `\n`），现在两条路共用轮次模块拼的 `\n\n`——这是恢复 R124 写下的契约。

### 7. 新模块与它的接口

- **`round`**（`crates/uva-tool-task/src/round.rs`）：`RoundInput` → `RoundResult`。
  - 输入：同伴、提示、父/子会话 id、名字、深度、写入器、收件箱、取消令牌、隔离、进度
    出口；
  - 结果：文本、结束原因、结局、**补丁**、子会话 id、名字。
  - 结果**携带补丁**是接口承诺：结果值就是这一轮的全部故事（说了什么、为什么结束、
    改了什么）；工件集**借用**这份补丁，不再整段拷贝一份。
- **`round::depth`**（`crates/uva-tool-task/src/round/depth.rs`）：`DepthLedger` 是深度
  的**唯一**判定与记账处。深度表随句柄的释放一起清：停放的子会话与被 kill 的子会话
  都清（终态子会话不会再跑一轮，没人读它的深度）。
- **隔离与验证门留在调用方**：要不要隔离、要不要过门是那次委派的决定。`Isolation`
  这个 seam 存在的理由是**反转补丁的计算时机**——补丁只能在 worktree 还在的时候算，
  所以轮次在调用方拆掉 worktree 之前向它要 diff；**不是为了多态**（它今天只有一个
  adapter）。

### 8. 记账只记一次

两条路各自抽干同伴时记 token 与轮次（`SubagentUsage`），各自的尾巴各落一次
（名册结算 + `subagent_exit` 脚手 + 工件集）。「一轮记一次」由**分路径断言**钉住：
委派跑完是 1，再唤醒一次是 2——总数相同但「一条路记两次、另一条记零次」也会得到 2，
所以断言必须分路径读。

## Considered Options

- **把深度规则留在两个调用方里**：被否。那正是本 ADR 要收的：两套答案里有一套（唤
  醒路径）根本没有上限。
- **把上限的主体改成「孩子」**：被否。判定的主体是**发起轮次的那一方**；孩子的深度
  是记账。改成孩子会让唤醒路径在「孩子已在上限层」时也拒——那是树没有变深的事。
- **结局词新造一套（`done` / `stopped` / `broken`）**：被否。既有词汇已经有三个词够用
  （退出脚手与运行时结束原因都在用），新造词只是多一种说法。
- **失败文案也换成结局词**：被否。原因是更细的一根轴，换掉就丢了「为什么」。
- **`Isolation` seam 删掉（让轮次自己管 worktree）**：被否。worktree 生命周期是委派的
  决定（要不要隔离），且补丁的**计算时机**必须反转：轮次要在调用方拆 worktree 之前
  拿到 diff。
- **结果里不带补丁（只留文本与结局）**：被否。结果携带补丁是接口承诺——结果值就是
  这一轮的全部故事（说了什么、为什么结束、改了什么）。代价只是工件集**借用**这份
  补丁，而不是再整段拷贝一份。

## Consequences

- **模型可见的行为变更**（CHANGELOG 随记）：
  1. 名册活动行 `finished` → `completed`、`failed` → `error`；L1 进度行同样。
  2. `agents_message` 在调用方坐上限时拒绝新起一轮（原先不拒）。
  3. 委派路径的失败文案里句柄行前多一个换行；两条路的失败文案逐字相同。
  4. 失败文案带上结束原因的详情。
- **公开面**：`uva-tool-task` 的模型面（`task` 工具的 JSON 形状与返回文本）按上述四条
  变；crate 的 `pub use` 计数不变。`ControlRegistry::kill` 收进 crate 内，公开的
  `ControlSurface::kill` 是唯一的 kill 入口——它顺带清掉终态子会话的深度条目。
- **测试面**：轮次模块自带每个结束方式的测试；两条路的结果同形由分路径断言钉住；源码
  门（`tests/child_round_module.rs`）断言轮次流程的调用方集合恰好是 `src/round.rs`。
